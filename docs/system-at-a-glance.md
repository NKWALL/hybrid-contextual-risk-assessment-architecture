---

## 一句話

**這不是把公開內容的審查機制套到聊天室，而是為私訊重新設計的風險偵測系統：風險被建構成「隨互動歷程逐步累積的狀態變數」，而非單則訊息的二元判定。**

## 為什麼要這樣做

同一句「你在哪」——

- 約好見面時傳 → **無風險**
- 對方已回「跟朋友吃飯」後、90 秒內連發第四則、還要定位 → **需要介入**

**字面完全相同，風險天差地別。** 差別在脈絡、在累積、在對方有沒有表達拒絕。任何只看單則訊息的分類器，結構上就抓不到這件事。

---

## 判斷什麼

**五個風險維度**，以「**作用機制**」分類（非語感或語氣強度），故可 multi-label：

| 維度 | 判斷關鍵（一句話） |
|---|---|
| `sexual_boundary` | 是否將互動推向性領域或私密空間 |
| `coercion` | 是否存在「不照做會有後果」 |
| `manipulation` | 是否在改變「對方怎麼理解這段關係」 |
| `harassment` | 是否忽視對方界線並持續干擾 |
| `emotional_pressure` | 是否透過情緒負擔而非威脅來促使讓步 |

**五個風險等級**，對應不同強度的介入：

`safe` → `observation` → `warning` → `restricted` → `blocked`

> 維度回答「**是哪一種**風險」，等級回答「**有多嚴重**」。同一維度可落在任何等級。

---

## 怎麼判斷（9 步）

```
Step 0  Guardrail      禁詞 + 分類器，一律只標記不攔截
Step 1  Context        讀對話歷史 + L1 語意摘要 + L2 關係指標 + 既有風險狀態
Step 2  Rule Δ         行為訊號計分（連發、字數失衡、未回覆仍持續）
Step 3  NLP Δ          LLM 依五維度機制定義給分 + 輸出判斷依據
Step 4  Fusion         依 NLP 自評信心動態加權（信心低 → 規則為主）
Step 5  Scenario       二階複合情境（深夜×性暗示、熟識降權、grooming 加速…）
Step 6  Final Δ        本則訊息的最終風險增量
Step 7  State Update   累積 = 舊狀態×衰退 + 新增量，並套用回饋校正
Step 8  Risk Level     composite = 0.60×最高分 + 0.30×活躍維度比例 + 0.10×趨勢
Step 9  Intervention   依等級對寄件方／收件方分別產生指令
```

**等級邊界**（composite 落在哪一段）：`0.10` → observation｜`0.20` → warning｜`0.45` → restricted｜`0.65` → blocked

**另有單一維度覆寫**：任一維度 ≥ `0.85` 直接 blocked，不看 composite。這是為了避免「一個維度極高、其他都低」被平均稀釋掉——與上面四條邊界是**不同的機制**。

**兩個設計重點藏在 Step 8**：
- **`spread`（0.30 權重）** ＝ 同時活躍的維度比例 → **同樣強度下，維度越多等級越高**
- **`decay`** ＝ 舊風險會隨時間與訊息數淡出 → 系統會「原諒」，不是永久記仇

## 三個定義性的設計決定

**① 介入是不對稱的**

同一則訊息，寄件方與收件方看到不同東西：

| 等級 | 寄件方 | 收件方 |
|---|---|---|
| `observation` | **無**（僅內部記錄） | 低調安全提示圖示 |
| `warning` | 柔性反思提醒 | 安全資訊卡 |
| `restricted` | 強制警告 + 冷卻 60 秒（**訊息仍送達**） | 保護卡片 + 封鎖／檢舉選項 |
| `blocked` | 攔截 + 冷卻 30 分 | 攔截通知（看不到原內容） |

寄件方側要**降低抗拒**（高控制語言會提高反抗、降低順從），收件方側要**情緒支持**。

**② Guardrail 只標記，不決定結果**

**沒有任何詞句在所有脈絡下都危險**——「傳裸照給我」也可能出現在新聞引述裡。因此禁詞與分類器一律只 flag，交由完整 pipeline 依脈絡判斷。`blocked` 仍到得了，但由 composite 決定，不由關鍵詞決定。

**③ 回饋是閉環，而且只放大不生成**

介入 → 收件方回饋（舒服／不舒服）＋ 背景模型第二意見 → 匯總成訊號 → 影響**下一則**的衰退與增量。

但這個訊號**不產生風險**：`alert` 只在「已有正風險」時才加分。規則與 NLP 都判無風險時，回饋機制加不出任何分數。

## 降級處理的定位

**NLP 掛掉本身就是架構失效，不應期望產出與正常時同等的準度。**

三個降級機制（`nlp_degraded`、`guardrail_degraded`、等級下限）的設計原則都是**不假裝**：
標記失效、保證不在自己壞掉時回答「安全」，但**不補償分數、不宣稱是哪種風險**。

真正該做的是上游的穩定性與分流，而不是在下游堆補償邏輯。
**降級時系統只能說「這裡值得看一眼」，不能說「這裡有什麼」。**

> 見 `known-issues.md` 設計決策 D6。

## 三個誠實的限制

1. **尚未在真實訊息分布下驗證**。設計案例約四成有風險，真實對話可能不到 1%——誤報的絕對數量會遠高於本評估結果。
2. **唯一的人類標註者即系統設計者**。已用「裁決版／多數決版」兩版參考答案做敏感度分析緩解，但建議補一位獨立標註者。
3. **三個 LLM 標註者的獨立性有限**。不同廠商的模型訓練語料重疊，其一致性不宜宣稱為「多方獨立驗證」；準則清晰度應以「人 × LLM」的一致性（0.897–0.913）為據。

## 如果只能記住三件事

1. **風險是累積的狀態，不是單則訊息的標籤。**
2. **關鍵詞只標記，脈絡才決定結果。**
3. **介入是不對稱的，而且會因回饋而校正。**
