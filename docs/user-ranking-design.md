# 使用者排序評估設計規格（實驗二）

> 對應 `evaluation-roadmap.md` §7.7。建立日期：2026-09-22。
> 用途：在接近真實比例的人群上，用排序指標回答「有問題的人挑不挑得出來」與「累積有沒有貢獻」。
> 與案例池（`case-pool-design.md`）互補：案例池測「等級對不對、什麼時候抓到」，本實驗測「挑得出來嗎」。

---

## 0. 定位

| | 案例池（實驗一） | 本實驗（實驗二） |
|---|---|---|
| 單位 | 標註點 | 人（一段對話的寄件方） |
| 問題 | 判的等級對不對、何時抓到 | 有問題的人排不排得到前面 |
| 資料 | 少而精，逐點五級標註 | 多而粗，每人一個二元標籤 |
| 指標 | QWK、Recall、FPR、介入時機 | P@10、AP |
| 閾值 | 依賴 | 不依賴 |
| 類別比例 | 約四成有風險 | 約 9% |
| 累積 | 介入時機直接量 | 消融間接量 |

兩者共用 `run_eval.py` 的序列執行與 trace 格式；本實驗不需要標註點、不需要五級標註。

---

## 1. 資料規格

### 1.1 人群組成

| 群 | 人數 | 必含 |
|---|---|---|
| 有害 | 10 | 五個維度各至少 1 人；**3–4 人慢速升溫**（每則單獨看不到 warning，累積後跨級）；≥1 人單一維度極端、其他乾淨（觸發覆寫）；≥1 人前半施壓、後半安靜（測「最高點 vs 結尾」的差異） |
| 安全 | 100 | 70–80 人一般正常互動；**20–30 人難負例**：求助（自己或朋友遇到威脅）、新聞／戲劇引述、親密但雙方合意、深夜正常關心、熟識間的玩笑、情緒低落但非施壓、一方話多但對方持續回應 |

「慢速升溫」在生成後要用 trace 驗證：該人每一則的 `risk_delta_total` 最大維度 < B_WARNING，
整段最高 `composite` ≥ B_WARNING。不符合的重生。

### 1.2 每人一段對話

| 欄位 | 規格 |
|---|---|
| 長度 | 10–14 則，寄件方為被評估的人；收件方有回應（不是獨白） |
| 時間戳 | 相對間隔保留；執行時整段平移對齊（同 `evaluation-roadmap.md` §6） |
| 關係背景 | `relationship_facts`、`relationship_summary`、`seed_metrics`，與案例池同格式；有害與安全兩群的關係階段分佈要相近（避免「熟識＝安全」這種捷徑） |
| 識別 | 每人獨立 `conversation_id`、`sender_id` |
| 與案例池的關係 | 不重疊；不進 dev；不做標註點 |

### 1.3 生成

- LLM 生成，提示裡**不放**系統規則、閾值、涵蓋檢核表或本文件
- 有害群依維度與升溫型態分別下提示；安全群的難負例逐類下提示
- 生成後去重、檢查長度與時間戳格式

### 1.4 人工檢查

每人一個標籤，由至少一位人類檢查（建議兩位，分歧討論）：

> 整段看下來，把自己放在收件方的位置（`annotation-rubric.md` §2.1），會不會覺得被施壓、越界或操控？

- `harmful`／`safe` 二元；可選加「最高應達等級」供事後分析
- 檢查者看不到系統輸出
- 被判與生成意圖不符的人：重生或改標籤，記錄原因

## 2. 執行

| 項目 | 規定 |
|---|---|
| 版本 | 調參定案後的系統；模型版本釘住；與測量 2／4 同一版 |
| 次數 | **只跑一次**；本實驗屬 test 性質，結果不回頭改系統 |
| 執行 | 每人種關係資料 → 依序送整段訊息 → 每則保留完整回應（等級、`diagnostic_signals`、三個 delta、`new_risk_state`、`intervention_command`）→ 清除 |
| 降級 | `nlp_degraded` 或 `guardrail_degraded` 為 True 的則數要記錄；任一人有降級則該人重跑，仍降級則標記並在報告排除或另列 |

---

## 3. 排序鍵與消融

### 3.1 完整系統

依序：

1. 整段最高 `risk_level`（含 `SINGLE_DIM_OVERRIDE` 拉上去的）
2. 同級內：整段最高 `diagnostic_signals.composite`
3. 平手：整段最高的單一維度值 → `sender_id`

用「最高點」而非「結尾值」：state 會衰退，前半施壓後半安靜的人結尾值會掉；人工標籤判的是「整段有沒有問題」，對應最高點。結尾值另算一次作敏感度分析。

### 3.2 消融：沒有狀態累積

| 版本 | 做法 | 隔離了什麼 |
|---|---|---|
| 零成本版（主） | 同一份 trace，改用「單則 `risk_delta_total` 最大值」排序 | 狀態累積（state 的跨則疊加與衰退） |
| 嚴格版（選做） | 每則重置 risk state 重跑，保留關係種資料，用 3.1 的排序鍵 | 同上，且等級也在無累積下重算 |

零成本版的「單則」仍含 NLP 的前文視窗與情境層，隔離的**只有**狀態累積；報告要寫明。

---

## 4. 指標與判定

### 4.1 指標

| 指標 | 算法 | 回答 |
|---|---|---|
| **P@10** | 前 10 名中有害者人數／10 | 挑不挑得出來 |
| **AP** | 沿排序往下，每遇到一個有害者記當時的 precision，10 個取平均 | 比 P@10 細的單一數字 |
| 有害者名次表 | 每人在完整版與消融版的名次並列 | 誰被漏、誰靠累積才浮上來 |
| 慢速升溫者名次 | 同上單獨列 | 累積的直接證據 |
| 誤傷清單 | 前 20 名內的安全者：是誰、屬哪類難負例、最高 composite 與主維度 | 哪類正常互動會被誤傷 |
| 敏感度 | 以結尾值取代最高點重算 P@10、AP | 衰退對排序的影響 |

### 4.2 判定（測量前定案）

- 報告 P@10 與 AP 數值，**不設及格線**——10 個正例，一個人就是 10 個百分點
- **累積有貢獻** ＝ 完整版 AP ≥ 消融版 AP，**且** 慢速升溫者在完整版的名次全部優於消融版
- 誤傷清單逐人解釋，歸類到 §1.1 的難負例類型；同一類被誤傷兩人以上要寫進 known-issues

---

## 5. 回答得了與回答不了的

| 回答得了 | 回答不了 |
|---|---|
| 不平衡人群中有害者的可分性 | 每個人該是哪一級（只有二元標籤） |
| 狀態累積對可分性的貢獻 | 介入的時機 |
| 接近真實比例下的誤傷樣貌 | 各層有沒有照設計動（那是涵蓋檢核表的事） |

---

## 6. 限制（寫進報告）

- 對話是生成的，9% 仍高於真實比例（<1%），部署後誤傷絕對量會更高
- 一個正例＝10 個百分點，P@10 只能看粗方向；AP 較細但同樣受 n 限制
- 人工檢查者若只有設計者一人，標籤與系統設計同源
- 零成本消融只隔離狀態累積，不隔離 NLP 前文與情境層
- 排序鍵含手定權重（composite 的 0.6／0.3／0.1），排序評估同時在評這組權重

---

## 7. 檢查清單

- [ ] 有害 10 人：五維度各 ≥1、慢速升溫 3–4 人（trace 驗證通過）、單維極端 ≥1、前半施壓後半安靜 ≥1
- [ ] 安全 100 人：難負例 20–30 人，七類各有
- [ ] 兩群關係階段分佈相近
- [ ] 生成提示不含系統規則與本文件
- [ ] 人工檢查完成，檢查者未看系統輸出
- [ ] 系統版本與模型釘住，與測量 2／4 同版
- [ ] 排序鍵、消融版本、判定規則在跑之前寫進本文件並不再改
- [ ] 降級則數已記錄
