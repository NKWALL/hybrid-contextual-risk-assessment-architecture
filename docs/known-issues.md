# 缺陷紀錄（節錄）

本檔為專案缺陷文件的節錄，收錄第一輪評估過程中找出、並已修正的五項系統缺陷。
完整的缺陷文件共 28 項，另有 6 條設計決策記錄（標明哪些行為屬刻意設計、不應被當成錯誤修掉），未一併公開。

---

## 1. 情境規則加分無上限

**修正前**：多條情境規則同時命中時，加成累加後超出值域，服務回傳 500。
命中越多條代表風險越高，卻反而讓判斷失敗。

**修正**：Step 6 將情境加成疊加後的結果夾在 0 與 1 之間。
下限存在的理由是抑制型規則（如雙方關係穩定熟識）原本可以把增量壓成負值，
語意上等於宣稱「這則訊息降低了這段關係的風險」，對死亡威脅之類的內容顯然不成立。

## 2. 熟識降權無條件套用

**修正前**：只要雙方熟識度夠高就套用降權，導致「你敢離開我 我就殺死你」被降為警告。

**修正**：降權規則加上 `nlp_all_below` 條件，
只有在本則訊息的五個維度全部低於 0.6 時才生效。
熟識可以提高對邊界語句的容忍度，但不能折抵內容本身已達警戒的訊息。

## 3. 語言模型未設 temperature

**修正前**：語意引擎未指定 temperature，同一則訊息重跑會得到不同等級（22 則中有 3 則）。

**修正**：固定 `temperature=0`。
需注意這只降低變異、並不保證確定性，實測仍觀察到同一輸入的維度分數存在差異。

## 4. 熟悉度公式有地板分

**修正前**：原式為 `0.40×訊息量 + 0.40×互動天數 + 0.20×發言平衡`，
平衡項為加法，雙方對稱時無條件貢獻 0.20。
全新對話的熟悉度即達 0.3059，而加速關係偵測的條件是熟悉度低於 0.30，
該規則在平衡對話下永遠無法觸發。

**修正**：平衡改為乘法因子，`(0.50×訊息量 + 0.50×互動天數) × 平衡係數`。
「對話單向就打折」才真的是打折，而非「平衡就送分」。

## 5. 多維度指標為二元計數

**修正前**：分散度採「超過門檻的維度數 ÷ 5」，
會把 0.12 的維度與 1.0 的維度算成同一票，把連續量壓成布林值。

**修正**：改用參與比（participation ratio），即 (Σx)² / (Σx² × 5)。
該測度為尺度不變，能區分「一個維度極高」與「多個維度中等」兩種不同的風險型態。
